# WorkBuddy 自动捕获实现与复验（2026-10-13）

当前工作区基于 v1.0.81，自动捕获改动尚未发布。本文覆盖本轮继续完成的代码及其验证边界。

## 架构事实与未知

上轮调查记录在 `.research/reports/N-全自动捕获可行性.md`。`wbKickHostSession` 原来就被调用，并非缺少调用。它处理 sidecar 的 `__workbuddy_cli_host__` 会话；聊天使用的 daemon 预热池 worker 不在该会话列表内。调查观察到 worker 的补充由 startup_ready / product_snapshot_change / post_acquire 触发，未发现补员心跳。

主进程重启用于触发新的预热 worker。此前观察到预热进程空载出网，**这些请求是否携带 Authorization 仍未真机确认**。因此实现提供自动重启路径，但不宣称已证明完全零操作捕获。

## 最终行为

- 凭据面板新增「允许自动重启客户端」复选框，默认不勾选。点击前说明窗口会关闭并重开、未保存内容可能丢失、客户端终端会话可能结束。
- 只有请求体的 `autoRestart: true` 开启重启。未勾选及旧调用方保留手动重启与手动填写路径。
- 进程查询包含 `.exe` 名称。必须匹配本次脚本所在安装目录，并唯一识别主进程；另一安装、CLI、sidecar、daemon、renderer、未知命令行与歧义候选均拒绝。
- 先验证 PID 启动时间，再按该 PID 请求退出；升级到强制终止前重新核验。身份无法验证时跳过终止，PID 已回收时不向接替它的进程发送强制终止。
- 启动客户端不附加参数，等待 spawn/error 事件；异步启动失败如实报告，不能声称没动过旧窗口。
- sidecar 必须属于本次安装目录且唯一。控制管道失败不直接杀 sidecar；可达时只发送常驻 CLI 会话的 session.kill，用户终端会话不作为目标。
- **不单独终止 sidecar/终端，与客户端整体退出后仍保住终端是两回事。** 后者无法由本实现保证，界面提前告知其影响。
- 从首次异步操作前占用捕获槽，避免两版并发覆盖状态和备份。定位、注入、捕获异常均进入最终清理。
- 无法保存磁盘备份时不注入。注入先截断再失败时恢复原文；确认脚本与备份原文一致后才删除磁盘备份，还原失败时保留备份供启动自愈。
- 未捕获到令牌只能报告「尚未捕获」，不能推断预热请求不带鉴权。超时结束后须重新开启捕获，再在新一轮等待中操作。

## 验证方式

`scripts/wb-auto-capture-test.mjs` 使用生产函数源码、假进程表、假启动事件、假 JSON-RPC 与假凭据。终止动作只允许指向测试自己创建的 Node 进程，拒绝镜像名和进程树参数。没有启动或终止真实 WorkBuddy，没有修改真实凭据配置。

`scripts/wb-capture-report-test.mjs` 验证长请求、终局轮询、默认关闭/显式勾选传参、成功/失败显示以及令牌脱敏。其服务端实例使用临时数据目录。

`scripts/wb-auto-capture-sabotage-run.mjs` 在临时副本中运行，先要求未改坏基线全绿，再逐条恢复危险行为，验证测试会失败。共享工作区不被改坏。

本轮全项目首轮回归为 590 项，589 通过；唯一失败是新增等待函数未登记到预算分类表，已补齐并定向验证。随后相关回归中出现一处测试文案匹配仍要求旧措辞，已调整为验证「打开客户端」的实际指引并复验。

最终结果：自动捕获 26 项基线全部通过；捕获报告、PID 身份及超时预算相关测试经分批复验通过；6/6 条反向对照在全绿基线的临时副本上产生失败，副本恢复校验通过；项目 C1–C15 闸门为 0 error / 0 warn，后端及卡片语法检查通过，git diff --check 通过。没有将首轮全项目命令的非零退出码表述为「全量全绿」。
