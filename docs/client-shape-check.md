# 客户端配置形状核对：怎么核、这次核出什么、局限在哪

> 对应 `docs/replication-plan.md` 的 **T15-e**（「形状要按用户本机这一版核」）。
> 工具：`scripts/clients-shape-check.mjs`（**只读**，不进 `npm test` —— 它要本机真装了那些客户端）。

## 为什么要有这一步

**magpie 那一版的形状 ≠ 用户装的那一版的形状。** magpie 是「它自己支持的客户端版本」的权威，
照抄它就能把用户配置写坏。2026-10-23 已经因此核出两个真坑：

1. **Hermes 的键名有版本差异** —— magpie 写 `providers:`（映射），**用户这版是
   `custom_providers:`（数组，元素里还自带 `model:` 字段）** ⇒ 照抄 ⇒ 用户的 Hermes
   读不到我们写的那一块。
2. **ZCode 3.14 把 provider 搬到了 `provider_config.json`**（rules 形状），
   `config.json` 只在启动时 import 一次 ⇒ 加在 `config.json` 里的 provider
   后来**再也进不了**它的选择器。

⇒ 所以每个客户端的形状都要**对着用户本机那一版**核。

## 怎么核（判据）

**「照着用户自己配过的那家学」** —— 这是唯一可靠的样本来源：

1. 拿我们要写的那一块（某个父路径下的新子键）；
2. 在**真实文件**里找**同一父路径下、用户自己配过的那些块**；
3. 拿其中一个当样本，比**键名集合**：
   - 样本有、我们没有 ⇒ 客户端可能需要（照它那份就该有）；
   - 我们有、样本没有 ⇒ 客户端可能不认（照它那份就没有）；
4. **标量**项（像 Claude Code 的 `env`：每个键一个字符串值）⇒ 比的是
   **同级键名**（这个客户端认哪些 env 键，答案就在用户自己写的那些键里）。

**只取键名与类型，一个值都不打印、不落盘、不写回真实文件。** 接线写到临时目录，真实文件只读。

## 这次核出来的（本机 28 个客户端，2026-10-23）

| 客户端 | 样本 | 结论 |
| --- | --- | --- |
| **Cline** | 用户自己配的 `openai-codex` | ✅ **键名集合逐字一致**（`settings` / `updatedAt` / `tokenSource`） |
| **Claude Code** | 用户自己写的 `env` 块 | ✅ **我们写的 env 键同级都有**（`ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_DEFAULT_*_MODEL`…） |
| **ZCode** | 真实 `provider_config.json` | ✅ 我们写的是它的**子集**，一个不缺（`scripts/zcode-shape-check.mjs` 单独核过） |
| **Hermes / MiniMax Code / Codex / Qoder / Qoder CN / OpenCode / WorkBuddy AI / Claude 桌面版** | —— | ⚠ **无从比对**：用户**压根没配过第二家上游** ⇒ 没有同类块可当样本 |

⇒ **这一轮没有发现真问题。**

## 局限（重要，别把它当结论）

**「我们没有、样本有」这一条分不出两种情况**：① 我们**漏写**了客户端需要的键（真问题）；
② **用户压根没配过第二家** ⇒ 那条差异来自别的原因。而 ② 是**常态**（本机 28 个客户端里
只有 Cline 配过别家上游）⇒ 自动核出来的「可疑」多半是 ②。

⇒ 所以脚本的输出是**线索，不是结论**。判「到底要不要改」仍然要人对着**那个客户端的
文档/源码**看。

**本机核不了的那些** ⇒ 要真核，得：
- 装一份那个客户端并**运行一次**（让它自己生成配置），或
- 照它的官方文档/源码核键路径。

## 怎么复跑

```bash
node scripts/clients-shape-check.mjs
```

⚠ 它会读**用户真实配置**（只读）⇒ 只在你自己的机器上跑。它**不改**任何真实文件。
