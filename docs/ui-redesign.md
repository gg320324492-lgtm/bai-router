# 面板改版规划（v1.0.97 起）

> 一句话：把面板从「**八家渠道各占一屏的设置表单**」改成「**先给答案、再给证据、最后给设置**」。

---

## 0. 为什么要改（问题陈述）

不是「不好看」，是**结构性的四个问题**（都是实际观察到的，不是猜测）：

1. **凭据页要滚很久才能看完八家。** 每家一个整块（含说明、输入框、按钮），
   八家 = 一屏半。改一家要看下一家在哪儿。
2. **渠道矩阵是 4×2 的固定网格。** 加了插件渠道就排不下；每格是**一段文字**
   而不是**一个状态** ——「这格现在什么情况」要读完文字才知道。
3. **诊断藏在折叠抽屉里。** 出问题时（额度用尽、令牌过期、上游 400），
   最该被看见的东西恰好是**收起来**的。
4. **同一个信息有四种样子。** 「已配置 / 未配置 / 冷却中 / 休息中」在四张卡里
   是四套措辞与四种颜色 —— 用户得自己在脑子里翻译。

还有一个结构性的隐患：**卡片是各自自建盒子的**。好处是隔离，坏处是**风格必然漂移**
（间距、圆角、字号、状态色各写各的）。

---

## 1. 信息架构：六屏，每屏回答一个问题

用户打开面板时，脑子里其实是这几个问题。按**问题**分屏，而不是按**功能**分屏：

| 屏 | 回答的问题 | 主内容 | 状态 |
| --- | --- | --- | --- |
| **总览** | 现在能用吗？ | 状态条 + 渠道热力图 + **常驻诊断** + 流量占比 | 保留（重做） |
| **渠道** | 这家怎么配的？ | **左列表 + 右详情**：凭据 / 模型 / 映射 / 账号 | **新建（主从改造）** |
| **流量** | 钱花到哪儿了？谁在扛请求？ | 每家流量与延迟 + 花费 + **请求时间线** + 会话亲和 | **新建** |
| **额度** | 谁快用完了？ | 每家预算 / 上游余额 / 休息状态 | 已建（扩） |
| **故障转移** | 出事时怎么换人？ | 转移链 + 策略 + 冷却与休息 + 插件 | 保留（重排） |
| **设置** | 这个软件本身怎么配？ | 端口 / 代理 / 更新通道 / 备份同步 / 数据目录 | 保留（重排） |

**关键决定**：渠道的**配置**从「凭据」屏挪到新的「渠道」屏，
凭据屏就此消失（它本来就是「每家渠道各自的凭据」= 渠道页的一部分）。
旧屏用 `location.hash` 重定向到新屏，不留死链。

## 2. 三条设计原则

1. **状态是数据，不是装饰。**
   每个渠道在任何地方都显示**同一个状态**，由**一处**算出来、一处着色。
   状态只有六种，全局一致：

   | 状态 | 含义 | 色 |
   | --- | --- | --- |
   | `ok` | 可用 | --ok |
   | `cooling` | 瞬时冷却中（等一会儿就好） | --warn |
   | `resting` | 休息中（额度/预算/令牌问题） | --warn |
   | `exhausted` | 预算用完 | --err |
   | `unconfigured` | 没配上（缺凭据 / 没登录） | --idle |
   | `unknown` | 探不到 / 状态不明 | --idle |

   ⚠ **「探不到」与「坏了」分开**（`unknown` vs `err`）—— 混起来会让用户以为账号被封了。

2. **一屏一个答案。** 每屏的第一眼要能看到那个屏的答案，细节往下滚。
   （例：额度屏第一眼是「谁快用完了」，不是「预算怎么填」。）

3. **不藏坏消息。** 诊断**常驻总览**（有问题时它就是第一眼），抽屉只作补充。
   同时**不喊狼来了**：一切正常时诊断区就一句话「没有观察到失败」。

## 3. 要造/要改的组件

| 组件 | 是什么 | 解决哪条 | 谁做 |
| --- | --- | --- | --- |
| `channel-state.mjs` | **状态计算层**：一个渠道 → 六态之一 + 原因 + 数字 | 原则 1 | agent |
| `StateBadge` | 状态徽章（色 + 字 + 图标点） | 原则 1、问题 4 | agent |
| `Meter` | 统一的小量条（百分比 + 阈值着色） | 问题 4 | agent |
| `ChannelHeatmap` | 渠道热力图：一家一格（状态色 + 在途/配额） | 问题 2 | agent |
| `StatusStrip` | 顶部横条：服务 / 当前接的 / 流量 / 用量 / 额度 | 一屏一答 | agent |
| `Timeline` | 请求时间线（审计台账的记录流，可筛） | 新流量屏 | agent |
| **渠道页主从布局** | 左列表 + 右详情 | 问题 1 | **我**（动 panel-common.js） |
| **CSS 尺度系统** | 4 级间距 / 3 级圆角 / 5 级字号 | 问题 4 | **我** |
| **模板骨架重排** | provider.html 的六屏容器 | 全部 | **我** |

分工的原则不变：**共享且脆的（CSS、模板、渲染层）我独占，其余 agent 并行。**

## 4. 视觉系统

- **沿用现有令牌**（`--ink/--ink2/--dim/--panel/--panel2/--panel3/--line/--line2/
  --ok/--warn/--err/--idle/--brand` + 各自的 `-soft`）。
  **不引入新配色** —— 语义色是 C7 闸门在两套主题里逐个查的，多一个颜色多一份漂移。
- **尺度**：间距 4/8/12/20，圆角 6/10/14，字号 11/12/13/15/18。
  卡片之间**同一屏内**用同一档，跨屏不变。
- **两套主题都要验**：新组件在深色与浅色下都得能读（对比度 ≥ 4.5:1）。

## 5. 迁移路径（每阶段可独立发布、独立验收）

| 阶段 | 做什么 | 验收 |
| --- | --- | --- |
| **P0**（已做） | 「额度」屏 + 配额真探测 | 活体用例（探测/预算/休息） |
| **P1 地基**（已做） | `channel-state.mjs` 状态层 + StateBadge/Meter 组件 | 同一渠道在各处状态一致的用例 |
| **P2 总览重做**（已做） | 热力图 + 诊断常驻 + StatusStrip | 截图对比 + 诊断可见性用例 |
| **P3 渠道主从**（已做） | 渠道页改主从布局，旧的凭据屏重定向 | 「改一家不用滚」的用例 + 旧 hash 不 404 |
| **P4 流量页**（已做） | 时间线 + 花费 + 会话亲和 + 价格表「用户点了才更新」 | 端点活体用例 + 价格表刷新活体用例 |
| **P5 收尾**（共享层已做，卡片层在做） | 空/错/加载三态齐全、键盘可达、窄屏 | 每张卡三态都有 + a11y 检查零问题 |

**P5 的共享层做了什么**（2026-10-23）：
- **三态组件**（`panel-kit.js` 的 `emptyState` / `errorState` / `loadingState`）：
  同一个意思在二十张卡里说二十种话（「还没有记录」/「没有数据」/「空空如也」…），
  用户得自己认出「这几种说法是一件事」。三态只在这里定义一次，且**三件事不许混**：
  空态不是出错；错误态**必须带下一步**（「加载失败」是猜谜）；
  加载态要能被读屏认出（`role="status"` + `aria-busy`）。
- **键盘可达**：跳过导航、切屏后焦点跟着内容走（只对键盘操作生效）、
  Esc 关浮层、**全局**焦点环（之前只有三处有）、tablist 的标准键盘行为
  （roving tabindex + ← → Home/End，tab 与 tabpanel 用 aria 配对）。
- **窄屏**：5 个宽度 × 6 个视图实测**零横向溢出**（`scripts/p5-a11y-check.cjs`
  跑真 Electron 窗口，报告在 `docs/evidence/p5-a11y-report.json`）。

**关于「不多发请求」这条硬约束**（面板每 5 秒轮询一次）：
- 面板轮询打的是**本机**的 `/api/status`、`/api/usage`、`/api/quota/overview` ——
  它们读的是本机状态与账本，**不打上游**。
- 唯一会上游的是**额度探测**：每 5 分钟一轮、每家最多 2 个只读请求
  （`GET`/`HEAD`），**没配凭据的一家都不发**（探测自己那道闸），上游回 4xx/5xx
  一律算「探不到」、**不重试**。探测结果缓存 5 分钟，所以「额度」屏开着时
  每 5 秒轮询也不会多打上游。

**P3 的第一步已经落地**（2026-10-22）：凭据页改成**手风琴** —— 一行一家，
收起也看得见状态药丸；状态是 warn/err 时**原因直接摆在那一行下面**（不藏坏消息）。
「旧 hash 不 404」这条同时成立：`#/cred` 落在这张手风琴上。

**顺手修掉的两处「同一件事两种说法」**（改版原则 1 的守门人）：
额度屏的状态列原先自己算一套（没配凭据也说「可用」），现已改用**全页共用的那份状态**；
探不到时原先把整句原因印在表里（八行铺开一堵字墙），现改为只写「探不到」、原因进悬停提示。

## 6. 不能破的东西（硬约束）

- **C1–C15 闸门全绿**（清单完整性、卡片表双向、语义色两主题、契约 id 只许加不许改…）。
- **`provider.html` 的 52 个契约 id 只许加不许改**（这是与别的模块的接口）。
- **8 个旧中转端口的行为一字不变** —— 面板改版不许顺手动中转。
- **面板离线可用**：没外网也要能看状态（探测失败只影响「上游余额」那一格）。
- **不多发请求**：新屏多了不等于请求多了（探测 5 分钟缓存、账本读一次）。
- **老链接不失效**：`#/cred` 之类要能落到新屏上（重定向，不是 404）。

---

## 7. 怎么验收

1. **活体**（真起服务、真面板、真上游）：每阶段一条，不许只截图。
2. **状态一致性**：同一个渠道在六屏上的状态必须一致 —— 一条用例查遍（这是原则 1 的守门人）。
3. **视觉回归**：关键屏的截图存进 `docs/evidence/`，改版前后对比。
4. **性能**：面板首屏 < 1.5 秒（本机）、轮询不产生额外上游请求（用上游请求计数断言）。
5. **不测的东西**：动画、像素级美观 —— 那不是这个仓库的验收标准。
